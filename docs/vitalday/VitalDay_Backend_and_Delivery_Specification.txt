VITALDAY
Android application backend and delivery
Architecture data security AI integrations and acceptance criteria
English Android application specification
Prepared for K Balaganesh Rajah  |  28 October 2026  |  Version 1.1
Build VitalDay as a native Android client supported by a secure modular backend. Keep wellness coaching, clinical services, commercial payments and personal work planning in separate permission domains. Share only the specific records needed for each action.
This specification is intended for the engineering lead, Android developer, backend developer, product designer, clinical reviewer and delivery manager. It defines proposed implementation choices and release conditions. No provider account, cloud infrastructure, regulated service or production integration is provisioned by this document.
Recommended build choices
Kotlin and Jetpack Compose for Android, with an optional Wear OS companion.
A modular API service with PostgreSQL, protected object storage, background jobs and dedicated integration adapters.
A constrained AI service that uses verified structured inputs and reviewed source material.
Separate staff portals for clinician, pharmacist, operations and content roles.
Delivery status
This is a product and engineering handoff. Implementation, security assessment, professional review, partner agreements and release testing are required before a production APK or Play Store launch. Estimates in this document are planning assumptions, not vendor quotes or delivery commitments.

Use the Product and UI specification for navigation and visual intent. The UI asset package contains screen PNGs, design tokens and a requirements backlog suitable for importing into a project tracker.

Android modules and build behavior
Suggested modules are core designsystem, core database, core network, core permissions and feature modules for today, food, move, plan, care, reports and coach. UI state is immutable and data repositories are the only source of truth. Configuration changes must not reset timers or upload jobs. Use feature flags to disable a failing vendor or unapproved clinical capability.
Platform support
Propose Android 9 API 28 as the initial minimum, subject to a device survey. Health Connect requires an eligible device with Google Play services; it is built into Android 14 and later and supplied as an app on earlier supported versions. Check SDK availability at runtime. Select current stable SDK dependencies and the current Play target requirement at implementation and release, rather than locking this plan to a preview version. [S1]
Data flow access control and trust boundaries
End to end flow
Android authenticates with an identity provider using an appropriate OAuth or OpenID Connect flow. The API validates the token and authorization for each object. Structured records go to PostgreSQL; uploads use short lived signed access to a private quarantine area. Workers validate files, process approved jobs and publish status through the API. The app fetches job status or receives a generic notification to refresh.
Health Connect records first require Android permission on the phone. Cloud upload is a separate explicit purpose choice. Only a minimal consented subset reaches the server. AI receives a reduced context through the AI gateway, never direct database credentials or unrestricted access to reports, payment accounts or contacts.

Consent and revocation
Record purpose, scope, policy version, granted time, expiry and revocation for device import, cloud processing, AI, provider sharing, location, calendar and optional voice. Revocation prevents new use immediately in the authorization layer; cancel pending AI and sharing jobs. It does not automatically delete previously imported records. Offer a separate delete option and explain necessary clinical retention.
Clinical record integrity
Keep original uploads immutable and version corrected extractions. A clinician note is signed or finalized under their identity with an amendment history. Patients may correct self reported data but cannot silently overwrite a signed clinical record. Every share and view of a report creates a restricted audit event.

A watch normally syncs through its vendor app, which must write the required data to Health Connect. A separate Wear OS app may use Health Services for supported exercise or passive metrics. Bluetooth integrations require a known device protocol and separate testing. [S1 S2 S3]

Reliable import algorithm
Read granted types and a change cursor; fetch updates in bounded batches. Validate timestamps, unit and origin, then upsert by source identity and version. Process deletions, advance the cursor only after a successful transaction and recover an expired cursor by controlled resync. Do not reimport the app own written records in a loop. [S2]
For overlapping steps or activity calories, use the supported aggregation approach and source priority rather than summing duplicate devices. Preserve raw source lineage and store derived summaries separately. Do not count the same exercise energy twice. Sleep sessions cross midnight; compute duration from instants and map to a documented sleep day convention. Preserve naps and do not average overlapping stages as independent sleep.
Offline and battery behavior
Queue manual logs locally with a client generated request ID, then synchronize idempotently. Conflicting edits use record versions and a visible resolution path; financial and booking writes require a live server response. WorkManager schedules deferred sync within platform limits, so display last successful read and Sync now. Suppress data driven insights when measurements are stale or missing. Test permission revocation, airplane mode and process death. [S2 S3]
Nutrition and recipe processing pipeline
Trusted nutrition calculation
Search a licensed food source and an editorially reviewed local food catalogue. USDA FoodData Central offers food and nutrient lookup APIs but does not guarantee full coverage of Sri Lankan dishes. Keep source identifiers, dataset type, retrieval time and nutrient basis. Never expose provider API keys inside the APK. [S4]
For a confirmed food, nutrient amount equals grams consumed multiplied by nutrient per 100 grams divided by 100. Sum ingredients for a recipe, apply documented yield and edible portion assumptions, then divide by verified serving count. Calculations use deterministic code and compatible units; the language model does not invent numeric nutrient data. Cooking yield and local recipe variation must be reviewed.
Image analysis job
POST a restricted media upload → validate file → submit image job → identify candidate dishes and visible components → request missing portion and cooking details → retrieve food matches → calculate an estimate → return a structured draft → user confirms → create a meal entry. Save original photo only under the selected retention choice.

Food guidance and content operations
Review local recipes, household portion mappings and substitutions with a qualified dietitian. Store editorial version, reviewer and next review date. Advice based on a declared allergy must respect the allergy even when a photo match differs. Medical diet restrictions require a clinician approved plan and cannot be inferred from one lab value. Disable photo processing independently if quality falls below the agreed evaluation threshold.
Blood reports and clinical safety workflow
Extraction and confirmation
Validate MIME type by content, file size and page count; scan for malicious content and reject active or corrupted files. Quarantine files until checks pass. OCR produces a field level structured draft with original text, page coordinates and extraction confidence. Laboratory documents are untrusted data, so embedded instructions must never become AI system instructions.
A user compares the draft with the original and confirms analyte, value, unit, lab interval, patient identity and sample date. Ambiguous decimal separators, scientific notation, absent units or impossible values require correction. Keep the original and every corrected version linked. Readability or consistency failures return a clear error instead of a fabricated explanation.
Explain only what is supported
A deterministic engine compares verified numeric results with the report interval where applicable. A curated content layer explains the test in general terms. AI may summarize that content and suggest questions for a professional, with citations and uncertainty. It must not prescribe treatment, infer a diagnosis, invent reference ranges or decide a safe exercise intensity from a lab result.
Triage protocol
A licensed clinical lead must own the symptom escalation and laboratory follow up protocol before activation. Rules identify supported tests, populations, units, recency, limitations and review intervals. Critical value alerts require a validated extraction and an approved process; the app must not act as a replacement for the laboratory or clinician critical result service. User reported urgent symptoms bypass AI and payment.
Clinical governance and product claims
Conduct a feature by feature intended use assessment for Sri Lanka and each expansion market, including whether any diagnostic, treatment or monitoring function requires medical device oversight. Do not rely on a disclaimer to neutralize a clinical intended use. The FDA wellness and clinical decision support guidance can inform a future US assessment but does not establish Sri Lankan compliance. [S12 S13]
Launch gate
A named clinical reviewer approves educational content, exclusions, alert copy and the response process. Validate representative reports across laboratories and image quality levels. Unresolved field errors or unsafe advice block release. Keep report explanation behind a feature flag until clinical and privacy reviews are complete.
AI architecture evaluation and user control
Constrained orchestration
The app sends a purpose specific request to the AI gateway. The gateway enforces consent, minimizes identifiers, retrieves permitted context, selects reviewed sources and calls an approved model. It validates the structured output and applies clinical and content policy checks before returning a response. Food arithmetic and record access remain deterministic backend functions.
Separate tools can search a food catalogue, read the user selected metrics, propose a meal plan, propose a workout or draft a task change. Each tool accepts a small schema and derives ownership from the authenticated user. AI can prepare a transaction proposal but cannot charge money, book a clinician, dispense medicine, share a report or move a calendar item without the required user confirmation.
Suggested response contract
Return answer_text, purpose, cited_content_versions, input_record_ids, input_freshness, limitations, suggested_actions and requires_professional_review. Tool action proposals include an expiring proposal_id and a visible change summary. Unsupported requests produce a helpful limitation and an appropriate referral path. Do not display an unexplained numerical health score.

Use cursor pagination, bounded date ranges, request IDs and a consistent error envelope containing code, message, field_errors and retryable. The API checks authorization on every referenced object.

Request and response example
A meal entry request includes client_id, food_id, portion_g 180, meal_time 2026-10-28T12:30:00+05:30, meal_type lunch and expected food version. The server derives user_id, calculates nutrient totals and returns entry_id, source_version, kcal, available macros and recorded_at. A repeated client_id with identical content returns the prior result; conflicting content returns 409.
Use these resource names in the executable OpenAPI implementation. Support 401 expired login, 403 missing scope, 404 inaccessible record, 409 version conflict, 413 oversized file, 422 validation failure and 429 rate limited. Never return raw vendor errors or tokens to the client.

Booking and payment state machines
Booking transitions are available → held → pending payment → confirmed → checked in → completed. Alternative states include expired, cancelled and provider no show. A booking row lock or uniqueness constraint prevents two confirmations for the same slot. A valid late payment for an expired slot triggers reconciliation and refund or user chosen rebooking, never a silent conflicting confirmation.
Payment states are created, authorized, captured, failed, refund pending, refunded and disputed. Webhook processing is idempotent and independent of the app returning from checkout. Reconcile unresolved payments daily. Store transaction references rather than card data. Clinical service transactions must use a suitable external processor rather than Google Play billing under the current policy. Separately assess wellness digital subscriptions against Play billing rules. [S9]
Order and call recovery
Pharmacy states are requested, clarification needed, reviewed, quoted, accepted, paid, preparing, ready, fulfilled, cancelled and refunded. Preserve pharmacist decisions and prohibit unapproved substitutions. Test call disconnect, provider absence, refund failure and user loss of connectivity. Choose a secure call vendor with suitable health data contractual terms and regional service quality; branding alone is not evidence of compliance.

Permission and notification handling
Request camera for capture, foreground location for nearby services, microphone for voice or calls and calendar access only when needed. Android notification permission can be denied. Offer an in app reminder list and a route to settings without nagging. Use appropriate local scheduling and WorkManager for deferred jobs; exact alarms require checking platform and policy eligibility. Delivery timing is not guaranteed across OS, device and battery states. [S14 S15]
Unavailable partner behavior
Vendor timeouts return a visible unavailable state and preserve the user draft. Do not fabricate provider slots, pharmacy stock, sleep metrics or nutrient data. Manual data entry and local planning remain useful during outages. Each adapter has a sandbox mode, timeout, retry policy, quota monitor and a feature flag.
Security privacy and retention requirements
Security implementation
Use modern TLS, encrypted database and object storage, protected backups and managed keys. Store long lived service secrets in a vault and never in the APK.
Apply object ownership and recipient grant checks at the service boundary. Require multi factor authentication for clinical and administration accounts. Log privileged changes and restrict report access.
Use short lived upload and download access, content validation, malware scanning, redacted logs, dependency scanning and tested database migrations. Avoid sensitive data in analytics, crash logs, URLs and push messages.
Separate production and test environments. Use synthetic test records. Do not copy real blood reports into development or AI evaluation without a lawful approved process.

Sri Lanka readiness
The Data Protection Authority publishes the PDPA, its 2025 amendment and subsequent gazettes. Before launch, local counsel must confirm the provisions and commencement dates that apply, lawful grounds for sensitive health processing, cross border processing, required notices and data subject procedures. The plan does not claim a fixed enforcement date from an older announcement or automatic legal compliance. [S11]
User rights and incident response
Provide data export, correction, consent review, share revocation and account deletion with identity verification. Map deletion to files, derived summaries, queues, AI copies and downstream partners. Test backups restoring without resurrecting deleted records. Assign an incident owner, vendor escalation contacts and the jurisdiction specific notification process before collecting live health records.

Native behavior
Use a single Material ripple and collect the pressed interaction to animate a subtle scale. For confirmed number changes, animate from the last committed value and format with locale aware separators. Keep a stable text width and tabular digits. Hoist animation state outside recycled list items so scrolling does not restart it. Respect reduced motion and platform animator settings. [S16 S17]
Performance and asset loading
Cache assets, decode large images to their display size and reserve the image aspect ratio before loading. Animate transform and opacity for web controls. Avoid layout driven digit widths, decoding full size photos for a small icon or continuously animating every dashboard card. Cancel old number animations when new data arrives and settle to the current confirmed target when the screen becomes inactive.
Sync state contracts and interaction acceptance
State ownership and data freshness
The device repository owns availability, granted scopes, active sync identity, last attempt, last successful import and per type results. Read Health Connect on the authorized Android device rather than pretending that a cloud API can pair arbitrary hardware. Recheck scope immediately before every read. [S1 S2]
If server progress tracking is needed, POST /v1/sync-sessions creates an idempotent session for an authorized phone import. GET /v1/sync-sessions/{id} returns source, status, started_at, finished_at, last_success_at, imported_counts and failed_types. PATCH cancellation requests cancellation; it cannot undo data already committed. Server state covers uploaded batches only and does not prove that the watch itself completed its upstream sync.

Interaction acceptance tests
Press and release outside a target must cancel the action. A rapid double tap cannot create duplicate writes.
Keyboard focus remains visible, dialogs restore focus to the opener, and labels survive 200 percent text scaling.
Numbers use the correct unit and day, never change underlying data through interpolation, and do not animate unverified medical values.
Granting sleep only does not authorize steps. Wearable sync cannot change calories recorded as food intake.
Skeletons and spinners cannot continue indefinitely after a failure. A real timeout produces an explicit recovery state.
Verify Android animations, 60 Hz performance and reduced motion on representative physical devices. Verify the CSS preview on mobile and desktop browsers.
